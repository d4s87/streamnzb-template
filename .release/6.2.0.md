# DraCuLa StreamNZB Template 6.2.0

6.2.0 completes DraCuLa's release-automation workflow by adding a manually gated Publish Release path. It does not change filtering, scoring, trusted-tier policy, adaptive filtering, profile content, Define Library behavior, or formatter behavior. Compatibility remains StreamNZB 6.1.0 / Jhin 0.7.1, unchanged from 6.1.0.

## Release automation

This release adds the publication half of the release pipeline:

- A manually dispatched Publish Release workflow requiring an explicit version and exact expected `main` commit SHA.
- A read-only candidate validation gate that must pass before any privileged GitHub App token is minted.
- Fail-closed checks for stale `main`, existing tags, already-published releases, malformed release state, and duplicate exact-version drafts.
- Direct lightweight tag creation against the exact validated release SHA, followed by immediate bounded verification.
- Deterministic reuse or creation of the exact-version GitHub release draft under privileged credentials.
- `.release/<version>.md` remains the authoritative public release body; Release Drafter content is overwritten rather than trusted.
- Post-publication verification of the direct tag, release metadata/body, strict forward compare against the previous stable release, and the release-notification workflow.
- Conservative partial-failure handling: after tag creation, failures require human inspection rather than automatic tag deletion, movement, recreation, or publication resume.
- Bounded retries/polling for transient GitHub visibility and notification states without weakening fail-closed release safety.
