# DraCuLa StreamNZB Template 6.4.3

6.4.3 is a focused Vidhin Define Library sync: it updates the Movie/Show WEB T3 and LQ release-group classifications to match current upstream data. It does not change any production rule, scoring value, Best-N behavior, the formatter, or the StreamNZB/Jhin compatibility pin.

## Movie/Show WEB T3 and LQ classification sync

DraCuLa's release-group Define Library is generated from upstream Vidhin05/Releases-Regex data. A routine sync found two real classification changes since the library was last regenerated:

- `HHWEB` has been removed from upstream's Radarr/Sonarr Web T3 lists and no longer belongs to DraCuLa's `Movies WEB T3 Groups`/`Shows WEB T3 Groups` Defines.
- `126811` has been added to upstream's Radarr/Sonarr LQ lists and now belongs to DraCuLa's `Movies LQ Groups`/`Shows LQ Groups` Defines.

Losing WEB T3 classification has a real practical consequence for HHWEB: it also loses its exemption from the existing `Reject suspicious 4K upscale` rule. A qualifying 2160p HHWEB WEB-DL release can now be rejected outright when a trusted 1080p remux alternative exists and no other qualifying 2160p/UHD-tier candidate is present in the same result pool — the same outcome any other unclassified group already receives in that shape. Library results and 1080p HHWEB results are unaffected, governed by the same rule scope as before. This behavior is covered by permanent real-engine regression tests.

The `126811` addition feeds the existing generic LQ-penalty/adaptive-filtering mechanism the same way every other LQ-classified group already does — no new rule was added. Its practical trigger surface depends on how the pinned Jhin parser extracts release groups: a bare trailing `-126811` tag is not recognized as a release group by this parser version, while a letter-suffixed variant (e.g. `-126811A`) is — a parser characteristic, not a DraCuLa mapping defect.

No production rule, scoring value, Best-N behavior, the formatter, or the StreamNZB/Jhin compatibility pin changed.
